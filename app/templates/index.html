What is a Session?

After you log in, the server creates a session — a record that you are authenticated. A session identifier (stored in a cookie) is sent with every subsequent request so the server remembers who you are without asking for your password again.

⚠️

What is Session Hijacking?

If an attacker obtains a valid session identifier, they can replay it to impersonate the legitimate user — without knowing the password. This is called session hijacking or a replay attack.

🛡️

What Does This Lab Demonstrate?

This lab implements a dual-token proof system. Every session requires two separate credentials: a session identifier and an HMAC-based proof token. The demo shows what happens when an attacker has only the session identifier.

📋

What This Lab Does NOT Claim

This system detects a specific scenario: replay without the proof token. An attacker who steals both credentials may still impersonate the user. IP or User-Agent changes are not used as detection signals because they can change during legitimate browsing.
